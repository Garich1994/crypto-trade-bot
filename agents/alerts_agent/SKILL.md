# Alerts Agent (Сторож)

## Назначение
Фоновые одноразовые уведомления о срабатывании ценовых и индикаторных условий.
Уведомление — это **факт** о цене или индикаторе, а не рекомендация и не прогноз.
Сработав один раз, подписка гасится (становится `fired`).

## Честное ограничение
- Сторож работает **только пока запущен процесс бота** (открыто окно long polling).
  Закрыли бота — проверки не идут. Это честно сказано в `/start` и README.
- Данные берутся у Data Agent (кэш TTL 60с). Это публичные котировки Binance,
  возможна задержка; цена может пересечь порог между двумя проверками.

## Хранилище
SQLite `data/journal.db` (та же БД, что и журнал; `data/` в `.gitignore`).
Таблица `alerts`: `id, user_id, symbol, condition_type, threshold, direction,
status (active/fired), created_at, fired_at`. Все операции фильтруются по `user_id`.

## Типы условий
- `price_above` / `price_below` — цена выше / ниже порога;
- `rsi_above` / `rsi_below` — RSI(14, 1h) выше / ниже порога;
- `change24h_abs` — модуль изменения за 24ч ≥ порога (в %);
- `volume_spike` — объём ≥ xN от среднего (20 свеч, 1h).

## Фоновая проверка
Asyncio-задача внутри процесса бота, цикл каждые **120 секунд**. Активные подписки
группируются по паре — к Binance идёт один запрос на пару за цикл (кэш не даёт
дублировать). Сбой данных по паре пропускается (подписка остаётся активной).

## Интерфейс
- `add_alert(user_id, symbol, condition_type, threshold) -> dict`
- `list_alerts(user_id) -> list[dict]` (активные)
- `remove_alert(user_id, alert_id) -> bool`
- `run_check(fetcher=None) -> list[dict]` — проверка и гашение; `fetcher(symbol,
  need_klines)` можно подменить (для тестов).
- `evaluate_condition(condition_type, threshold, metrics) -> (fired, actual)` — чистая проверка.
- `set_db_path(path)` — переопределить файл БД (для тестов).

## Правила
- Только формулировка «условие сработало» — без «покупай/продавай/входи/сигнал».
- Данные не выдумывать: нет данных — подписка просто не проверяется в этом цикле.
- Методология частоты/формата адаптирована (прочитана, не установлена) из
  day-trader-skill (trader-alerts): алерт — факт, каждое условие срабатывает один
  раз, подтверждаем подписку пользователю, котировки не выдаём за «живые».
